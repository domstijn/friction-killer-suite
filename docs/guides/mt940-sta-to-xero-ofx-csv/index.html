Exact Symptom

Uploading raw SWIFT MT940 (.sta) files fails or lumps cryptic '?20' / 'EREF+' strings into a single unsearchable Xero Payee field.

Technical Root Cause

MT940 encodes statement lines across fixed 6-digit YYMMDD dates in :61: (including reverse-debit 'RD' and reverse-credit 'RC' indicators) paired with multiline :86: subfields (?00, ?20-?29, ?32 counterparty name, ?38 IBAN).

Technical FAQ

How are reversed entries (RD / RC) in :61: handled?

BankFeedBridge handles C (credit), D (debit), RC (reversal credit / negative credit), and RD (reversal debit / positive credit) automatically.

What if my bank uses Dutch slash tags (/NAME/, /REMI/) instead of ?32?

Both German ?XX SEPA subfield codes and slash-delimited /TAG/ MT940 structures are supported.
