How to Fix QuickBooks Error OL-222 for CAMT.053 & MT940 Bank Files

Why QuickBooks Desktop rejects converted bank files with Error OL-222 / OL-221: missing <INTU.BID>, invalid <CURDEF>, unescaped XML & duplicate <FITID>. Fix locally in Chrome.

Exact Symptom

QuickBooks Desktop shows 'QuickBooks is unable to verify the Financial Institution Information for this download (OL-222)' right after importing a .QBO Web Connect file converted from European CAMT.053 XML or SWIFT MT940.

Technical Root Cause

QuickBooks Web Connect refuses standard SGML/XML OFX files unless they contain a whitelisted <INTU.BID> financial institution code (e.g. 3000), valid OFX v1 header block, clean ASCII/escaped entities (&amp;), and deterministic <FITID> transaction IDs without SEPA batch collapse.

Technical FAQ

Is INTU.BID 3000 safe for European & UK bank accounts in QuickBooks?

Yes. Intuit BID 3000 maps to a generic whitelisted checking bank profile so QuickBooks imports EUR, GBP, or USD Web Connect transactions cleanly without Direct Connect credentials.

Will re-importing overlapping date ranges create duplicate transactions?

No, because BankFeedBridge computes deterministic <FITID> hashes per transaction from IBAN, booking date, batch index, EndToEndId, and integer-cent amount.
