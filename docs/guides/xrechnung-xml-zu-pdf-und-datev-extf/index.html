Exact Symptom

Lieferanten senden reine XRechnung-.xml-Dateien (UBL 2.1 oder CII) ohne eingebettetes PDF. In Excel öffnen sich hunderte kryptische Tags—und manche Desktop-Viewer stürzen ab.

Technical Root Cause

Im Gegensatz zu ZUGFeRD besitzt reine XRechnung kein PDF-Dokument, sondern besteht ausschließlich aus strukturiertem EN-16931-XML.

EN 16931 / UBL / CII FeldBedeutung auf RechnungZiel in DATEV EXTF / A4 PDF
BT-1 / IDRechnungsnummerBelegfeld 1 & PDF-Kopfbereich
BT-10 / BuyerReferenceLeitweg-ID / BestellreferenzKopfzeile & Buchungstext
BT-118 / CategoryCodeSteuerkategorie (S, AE, E, Z)Steuert BU-Schlüssel (9, 8, 94, 0)
BT-112 / PayableAmountBruttobetragUmsatz in DATEV (Komma-Format)

Verified Format / Code Snippet

<cbc:CustomizationID>urn:cen.eu:en16931:2017#compliant#urn:xeinkauf.de:kosit:xrechnung_3.0</cbc:CustomizationID>
<cbc:ID>XR-2026-1001</cbc:ID>
<cbc:BuyerReference>991-12345-67</cbc:BuyerReference>

Step-by-Step Local Resolution

  1. Step 1: Laden Sie eine oder mehrere XML-Rechnungen in EInvoiceLocal (bis 3 Dateien pro Stapel kostenlos).
  2. Step 2: Klicken Sie auf eine Zeile im Batch, um rechts die druckfertige A4-Ansicht per Strg+P / Drucken als PDF zu speichern.
  3. Step 3: Exportieren Sie mit Pro (€29 einmalig) komplette Ordner direkt als DATEV EXTF, Xero oder QBO CSV.

Technical FAQ

Funktioniert EInvoiceLocal auch für Peppol- und ZUGFeRD-XMLs?

Ja, UBL 2.1 (XRechnung & Peppol BIS 3.0) sowie UN/CEFACT CII (ZUGFeRD) werden automatisch erkannt.

Bleibt das gedruckte PDF GoBD-prüfbar?

Das gedruckte A4-PDF dient der schnellen visuellen Freigabe; für die GoBD-Archivierung bewahren Sie die ursprüngliche XML-Datei auf.
